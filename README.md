# BOTC Grimoire 血染钟楼说书人工具

局域网优先的多设备说书人工具:说书人电脑运行本地服务器,玩家手机扫码即可获得私密角色卡。无需域名、无需公网,手机热点 / 路由器 / ESP32 盒子均可兼容。

## 架构

- **后端** `backend/`:Python + FastAPI + WebSocket(游戏状态、实时推送、二维码生成)
- **前端** `frontend/`:Vue 3 + Vite 玩家页与说书人魔典；旧版仅作迁移回退资产
- 单端口部署:所有设备访问同一个局域网地址

生产构建产物由 FastAPI 同端口托管；运行时仍不需要公网或 Node.js。

## 快速开始

```bash
# 1. 后端依赖
python -m venv backend/.venv
backend/.venv/Scripts/python.exe -m pip install -r backend/requirements.txt
#    (网络不通时:no_proxy='*' NO_PROXY='*' ... -i http://mirrors.aliyun.com/pypi/simple/ --trusted-host mirrors.aliyun.com)

# 2. 启动(无需任何构建)
cd backend
.venv\Scripts\python run.py
```

- **说书人**:浏览器打开 `http://localhost:8000/#/storyteller`(默认密码 `grimoire`,可用环境变量 `STORYTELLER_PASSWORD` 修改)
- **玩家**:手机连同一 WiFi,扫描说书人界面上的二维码加入
- Windows 首次运行会弹防火墙提示,勾选「专用网络」并**允许**,否则手机连不上

## 前端开发与构建

前端使用 Vue 3 + Vite。开发服务器把 `/api`、`/ws` 请求代理到本机 8000 端口的 FastAPI。

```bash
# 前端开发
cd frontend
npm install
npm run dev

# 生产前端构建
cd frontend
npm ci
npm test
npm run build

# 生产服务器
cd backend
.venv/bin/python run.py
```

Node.js 只在开发和构建前端时需要。仓库会提交 `frontend/dist/`，因此生产环境
只需 Python 和已经构建好的静态文件，启动和游戏过程都不需要 Node.js 或互联网。
玩家页与说书人魔典都由 Vue 提供。旧版文件只在完成后端拆分与最终回归前保留作回退。

说书人电脑端正式入口为 `http://localhost:8000/#/storyteller`。Vue 页面提供实时三栏魔典、
开局配置、夜晚工作台、白天提名投票、旅行者与座位管理、私聊监管和结算复盘。
旧的 `/#/storyteller-preview` 会自动跳转到正式入口；夜晚写操作统一经过 `/api/night/*` 模块化接口。

存档使用 schema v2：身份、存活状态、能力状态与异常效果归属于座位，线上玩家只领取座位。
旧版存档会在加载时自动迁移；夜晚事件与效果都保留来源、时间和撤销依赖，便于复盘追溯。

## v1 已实现

- 四个脚本全收录:暗流涌动 / 黯月传奇 / 教派紫月 / **瓦釜雷鸣**(社区官混缝合板子 Catfishing,7~15 人),说书人可随时切换
- 说书人配置板子与人数(5~15,瓦釜雷鸣 7 起),座位按环形排布
- 玩家凭名字 + **4 位房间号**加入(说书人设定/随机,二维码自动预填,改号后新加入者需用新码),自选空座位入座(开局前可换座),身份存 localStorage,刷新不掉,断线自动重连
- 按官方配置表随机分配角色,支持脚本特殊规则:男爵 −2镇民/+2外来者、方古 −1镇民/+1外来者、亡骨魔 +1镇民/−1外来者、教父/气球驾驶员 −1镇民/+1外来者(原版为说书人二选一,工具默认 +1)
- 手动发身份:说书人逐座指定角色(硬校验恶魔恰 1、爪牙 ≥1);**无需等人入座**,可先把身份发到座位上,玩家入座自动继承,满员自动开局
- **人未齐也可开局**:随机分配直接给全部座位发牌(空座挂预发身份)并开夜;手动预发后点「🌙 开始游戏」强制开局。迟到的玩家扫码入座即继承该座角色(进行中只能坐空座,不能换座),空座角色的夜晚步骤照常排在流程里。**开局前玩家页不显示任何身份**——说书人开始游戏才发身份,入座继承仅在说书人侧可见
- **恶魔伪装(配版时选好)**:发牌时定下三个不在场的好角色(暗流涌动限镇民,其余脚本镇民+外来者)——随机分配自动抽取;手动发身份面板「🧪 伪装」区点选 3 个(被发到座位的角色自动移出候选,选满 3 个才能确认)。说书人推进到「恶魔会面」后,恶魔的手机角色卡才显示「伪装」,说书人的步骤卡同步展示方便口头告知。按真实身份判断,非恶魔(含看到假镇民的酒鬼)不可见
- **认知覆盖(配版时由说书人选定)**:疯子以为自己是恶魔、酒鬼看到假镇民——手动发身份面板「🧠 认知覆盖」区**框点选**(与发身份/伪装同一套点选交互,再点已选中的框=清除),疯子还须指定**以为谁是爪牙**与 **3 个伪装**(均由说书人定,不一定是真的),未选完不能确认;随机分配不自动抽,夜晚面板提示「认知覆盖待定」座位,在玩家详情里补选。假身份**允许与在场角色相同、不计算配板**(不标已用、不影响配比);夜晚步骤按座位真实身份显示 🍺 酒鬼 / 🌙 疯子图标。玩家角色卡只显示假身份,真实身份仅说书人可见;疯子手机同步显示假爪牙名单与假伪装;**恶魔与爪牙会面时都会被告知谁是疯子**(手机同步显示)
- **入夜会面指向**:「爪牙会面」步骤显示「👉 恶魔:座X」+「👥 爪牙同时醒来,彼此可见:座X、座Y」,「恶魔会面」步骤显示「👉 爪牙:座X」,说书人照着指向告知即可;空座上的预发角色也列出(显示「空(预发)」),与「唤醒」行区分——唤醒只列在座玩家。说书人推进到相应步骤后,**爪牙手机同步显示恶魔+其他爪牙(官方规则:爪牙同时唤醒,彼此认识),恶魔手机显示爪牙名单**(信息一旦给出不可收回,后续一直可见)
- **黑夜/白天自动换色**:整页配色随游戏阶段自动切换——黑夜=深夜蓝黑(月光蓝操作色),白天=白昼暖黄(保留血红操作色),说书人页与玩家页同步,带 0.6s 渐变过渡
- 玩家手机实时收到私密角色卡(其他玩家只能看到座位上的名字,看不到角色);玩家页展示**官方基础配比**(如「暗流涌动 · 6 人 · 镇民 3 · 外来者 1 · 爪牙 1 · 恶魔 1」)——男爵/教父等造成的实际调整**绝不**下发给玩家
- **哨兵(神职角色)**:说书人启用哨兵将外来者数量 +1 或 −1,也可选「**不变**」(在场但不调整);−1 仅在官方配比有外来者时可选,且仅开局前可改。随机发牌的实际配比随之调整(镇民反向补偿,总数不变),手动发身份面板的配比提示同步联动。哨兵是公开信息——玩家页显示「🧙 哨兵在场」提示,但**调整方向保密**
- 存活/死亡标记、移除玩家、重置本局,WebSocket 实时同步
- 夜晚流程助手:按官方夜晚顺序逐步骤推进(天黑→各角色→天亮),展示该步唤醒的座位与说书人提示;第 2 夜起首夜专用角色自动退出(小恶魔/共情者等每夜角色保留);瓦釜雷鸣按钟楼剧本博物馆数据定序;酒鬼认知覆盖会追加假角色步骤
- 状态标记:中毒/醉酒/疯狂/**角色转变/阵营转变**,同一座位可同时挂多个(角标横排并列不遮挡),可随时增删。**角色转变由说书人点选「变成哪个角色」**,所有展示角色的框按**新角色的阵营配色**(说书人座位角标 🔄厨师=镇民蓝、详情按钮同色;玩家角色卡直接换成新角色);**阵营转变由说书人点选新阵营(善良/邪恶)**,角标/按钮/玩家提示按阵营配色(善良蓝/邪恶红,如 ⚖善良)。**角色转变与阵营转变都会通知玩家本人**(手机角色卡显示新角色、卡框与阵营徽章随新阵营变色);其余标记仅说书人可见,玩家无感知
- 提名投票处决:白天发起提名(一人一票实时举手,票数达存活半数即变绿提示),处决/无效判定,当日提名历史,天黑进入下一夜
- 自动存档:每次变更原子写入 `backend/data/game.json`,服务器重启自动恢复;**读档**可撤销误操作(重置不写盘,点「读档」即回)
- 冒烟测试 `backend/smoke_test.py` 覆盖配置→加入→选座→分配→推送全链路,以及夜晚流程/标记/提名处决/存档读档/酒鬼伪装(先启动 run.py,可重复运行)

## 已知限制

- 角色文案均为初版速写,校对只改 `backend/app/roles.py`(瓦釜雷鸣与官方角色命名已对齐钟楼剧本博物馆社区通用名)
- 存档是整局快照(单文件),每局互相覆盖;多局并行 / 多桌暂不支持
- 旅行者(Travellers)未收录(瓦釜雷鸣的学徒/咖啡师/乞丐/集骨者/流莺也暂缺);迟到玩家通过继承空座预发身份入场,暂不提供旅行者机制
