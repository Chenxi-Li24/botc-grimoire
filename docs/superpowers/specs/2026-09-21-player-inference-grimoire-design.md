# 玩家推理魔典设计

## 目标与已确认规则

玩家在游戏进行中按座位记录自己推测的角色、异常状态和变化事件；说书人实时查看所有玩家的推测，其他玩家不能读取。结算后玩家能把自己的推理过程与真实记录对照。推理是玩家的主观判断，不参与游戏规则判定，也不能令真实角色或效果发生变化。

本功能不复用说书人真实状态标记：真实的中毒、醉酒、疯狂、角色变化与阵营变化仍由现有游戏状态和夜晚效果账本管理。玩家推理从不自动填入其他座位的真实信息。`酒鬼`是角色候选；`醉酒`是可能持续一段时间的状态，两者分别记录。

## 方案选择

采用服务端保存、按身份投影、沿用现有 WebSocket 实时推送的独立推理日志。纯本地存储无法让说书人实时看到，也无法自然跨本地地址／公网隧道同步；把推测发进私聊虽省接口，却无法按座位和轮次可靠复盘。推理日志与游戏事件日志分开，避免“猜测”被夜晚规则引擎当成事实。

## 权限前置条件

当前公开座位投影中的 `Player.public()` 含 `id`，而 `/api/me/{player_id}` 及玩家 WebSocket 又把同一个 ID 当访问凭证。仅做界面隐藏不能保证新笔记的私密性。启用推理魔典之前必须拆分公开参与者 ID 与私密、高熵的会话凭证：

- 公开座位只发送座位号、公开名字和公开状态，不发送可调用私有接口的凭证；说书人视图保留管理所需标识。
- 新玩家加入时取得独立的随机私密凭证；所有玩家私有 HTTP 接口、WebSocket 连接和推理写入按凭证验证本人，而不是相信请求体中的作者 ID 或座位号。玩家自己的视图可以包含自己的公开 ID，但不能包含他人的私密凭证。
- 说书人继续通过现有说书人身份认证查看全体推理，但不得改写玩家推理；普通玩家只能读取、修改自己的日志。任何公开座位、聊天、普通玩家投影、公共时间线均不包含别人的推理。
- 既有存档中的旧 ID 曾经出现在公开投影中，无法仅凭旧 ID 安全签发新凭证。上线时保留进行中的旧局玩法，不为无安全凭证的旧局开启私密推理；新局或经说书人核准的安全续接才启用。不得默默将公开旧 ID 升格为笔记凭证。
- 本地与公网是不同浏览器来源，不能自动共享本地凭证。要在两个入口恢复同一笔记，应使用一次性、限时的玩家续接码，由当前已认证设备或说书人核准发放；不能仅凭房间号、名字或座位领取已有笔记。

## 数据边界与记录模型

每局分配独立 `game_id`，不以可重复的四位房号作为唯一键。服务端按 `game_id + 作者公开 ID` 保存推理日志，每条记录的目标为座位号，或旅行者公开 ID。即使座位尚无人线上领取，已创建的线下座位仍可标记；座位随后有人领取时推理仍属于该座位，而非绑定玩家账户。旅行者的角色是公开信息，旅行者卡主要用于阵营、状态及备注推测。

日志为追加式变更，字段至少包括：服务端递增序号、作者、目标、类别、操作（设置／结束／清除）、内容、服务端记录时间，以及当时的昼夜、日／夜轮次。编辑或撤销不抹去旧判断，而是产生新记录；由日志派生当前座位标记。玩家可填写“推测从哪一轮起有效”，但该主观时间和不可伪造的服务器记录时间分开显示。

类别如下：

1. **角色／阵营猜测**：一名主要角色及至多两名备选角色，可独立标记善良／邪恶／未知、把握程度和简短依据。候选角色来自当前剧本的公开目录，不来自真实座位分配。
2. **状态推测**：`中毒`、`醉酒`、`疯狂`，各有推测起点、可选结束轮次或“尚不确定”，疯狂可选声称的角色。只是玩家判断，不按实际规则自动到期；玩家结束判断时保留历史。
3. **变化推测**：角色转变、阵营转变，记录怀疑发生的轮次、可选的前后角色或阵营和依据。未知的前后值可留空，不强迫玩家编造。

服务端限制目标、角色 ID、类别、字段长度和记录频率。无效提交返回明确错误而不改变日志；提交重试用变更 ID 去重。保存成功后才推送新投影，断线重连以服务端日志和当前派生状态恢复，避免重复记录。旧存档缺少新字段时默认空日志；存档与重启均保留笔记。结算后仍能复盘；重置本局前明确告知旧笔记会被清除，跨局永久档案不在首版范围内。

## 页面与实时数据流

玩家端在现有广场／行动之外提供独立“推理魔典”入口，继续使用环形座位。游戏操作模式中的座位点击仍服务提名等原有动作，不被笔记入口接管。推理模式点击座位打开编辑面板：角色图标与搜索、状态／变化标记、轮次、依据、当前判断和修改历史。圈上的图标与颜色都明确标为“我的推测”；空间不足时只显示主要角色图标及少量状态缩写，完整内容留在面板。未标记座位不显示虚假的阵营提示。

玩家提交后，服务端验证凭证和内容，追加日志、原子保存，再向作者和说书人的 WebSocket 推送各自视图。作者投影只含自己的笔记与公开角色目录；其他玩家投影绝不含该事件或他人笔记。说书人选择座位时，右侧默认折叠“玩家推测”，按作者列出最新推测及时间线，和真实角色／真实状态分区、视觉标签明确。说书人只能阅读，无修改或广播按钮；不弹出打断夜序的通知。

结算后，玩家复盘页显示自己的推测时间线及公开的真实结果。最终角色猜测可与最终角色对照；有可靠真实事件／效果历史的状态和转变可按对应轮次对照。若某种旧存档没有足够的真实历史，显示“无法核对”，绝不推断为正确或错误，也不提前给出结算前的真实答案。

## 主要改动边界

- 后端：独立推理领域模块、存档字段及默认加载、玩家写接口、鉴权与续接、玩家／说书人分别投影、复用实时推送；不把推理写入夜晚效果账本。
- 前端：独立玩家推理视图、座位编辑面板、推理服务与状态、说书人座位详情中的只读折叠区，以及结算对照；复用现有剧本角色 ID 和图标清单。
- 现有游戏行动、真实状态标记、私聊及公开广场保持原语义。未来 JSON／PDF 剧本导入只需提供公开角色目录，不依赖固定的官方角色列表。

## 验收条件

- 两名玩家分别做不同推测：本人及说书人实时可见，彼此视图、HTTP、WebSocket 中不可见；用另一玩家凭证读写会被拒绝。
- 公开投影不泄露可用于访问私有接口的凭证；旧局不因迁移被强制中断，且不会在无安全凭证时开放笔记。
- 线下未领取座位、旅行者、角色候选缺图、疯狂目标未知、角色／阵营变化前值未知均可正常记录或退化显示。
- 修改、结束、撤销标记保留顺序与服务端轮次；重连、同人多端、服务重启后恢复一致，重复提交不产生双记录。
- 玩家推测不改变说书人真实效果和夜序；游戏中的提名／夜晚选人不受推理座位点击影响。
- 结算前没有真实身份或真实状态泄漏；结算后仅对有依据的事实作正确／错误对照，旧存档缺失历史时显示无法核对。
