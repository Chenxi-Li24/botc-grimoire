# 玩家账户、游客续接与历史记录设计

## 目标和边界

玩家可以不注册，输入房间号和名字直接以游客加入；也可以注册或登录用户名＋密码账户。两种入口都能在掉线后恢复本局身份和原座位。账户额外提供跨局历史：仅本人曾扮演的角色、自己的推测过程和本局结算，不归档私聊。说书人在进行中的对局仍可实时查看玩家推测，但默认不能浏览账户的跨局私人档案。

本设计负责身份、续接、账户和历史归档。推测内容的具体编辑界面与事件模型沿用 [玩家推理魔典设计](2026-09-21-player-inference-grimoire-design.md)；身份体系先落地，推测事件接入后进入同一历史档案。两份设计共享“玩家推测只属于本人，说书人可看本局，其他玩家不可看”的边界。旧局已经结束，不要求用已公开的旧玩家 ID 无缝续接；但部署或迁移不得未经确认删除 `backend/data/game.json`。

首轮允许在可信局域网以 HTTP 测试。页面明确提示使用专用测试密码，不复用其他网站密码；不把明文 HTTP 暴露到公网。公网隧道若保持 HTTPS，可继续访问同一后端。HTTP 无法阻止同网段窃听密码或劫持会话，因此测试版不宣称具有生产级隐私；后续 HTTPS 升级不更换账户、参与者或历史的数据模型。

## 方案选择

采用本机后端的可选账户和服务端会话，不接入邮件或第三方身份服务。仅靠游客本地存储不能跨地址或设备找回；强制注册会打断现场扫码入局；外部身份服务会增加对互联网和运营账户的依赖。账户历史保存在服务器本地的 SQLite，当前局仍保留现有 JSON 自动存档。

一个人有三个不同层次的标识：

1. **账户 ID**：可选，跨局稳定；用户名只用于登录，不充当身份凭证。
2. **本局参与者 ID**：每局独立，绑定一个线上玩家或旅行者；座位和角色属于现有座位状态，不因手机掉线而消失。参与者 ID 可出现在公开名单，但不得授权私有接口。
3. **设备会话**：服务端签发的高熵随机秘密，按摘要存储，浏览器只在 `HttpOnly`、`SameSite` Cookie 中持有。一次登录可有多个设备会话，默认有效期 30 天；主动退出使该设备会话失效。账户会话跨局保留；游客会话仅用于已加入的本局。说书人只可撤销本局参与者的续接权限，不能撤销或登入玩家的跨局账户。

密码只存带独立盐的 Argon2id 哈希；不存原文、可逆密文或快速哈希。登录、注册、密码恢复与续接码兑换有频率限制，错误信息不暴露用户名是否存在。账户注册时给出一次性恢复码并只在当时显示；服务端只存其摘要。持有账户会话者可修改密码或退出所有设备。忘记密码时只能用恢复码重置；说书人无法仅凭房号或座位重置账户密码或读取跨局档案。

HTTP 测试阶段 Cookie 不设置 `Secure`，但仍设置 `HttpOnly` 和 `SameSite`，并对修改请求做 CSRF 防护和 Origin 校验；WebSocket 握手也验证 Origin 和会话。部署到 HTTPS 后由明确的部署配置启用 `Secure`，不信任客户端随意提交的转发协议头。无论传输方式如何，都不把会话秘密放进 URL、公开投影或 `localStorage`。

## 加入、登录与身份绑定

入口页提供“游客加入”“注册”“登录”。游客沿用房号＋名字，服务端创建本局参与者和设备会话；注册或登录只建立账户会话，进入房间时仍需房号，本局首次加入才创建参与者。一个账户在同一局最多关联一个参与者；已关联时登录直接返回原身份和原座位，不创建重名玩家。

已入局游客可在自己的设备上注册，并把当前参与者与新账户原子绑定。游客登录已有账户时，如果该账户尚未参加本局，则把当前参与者绑定到账户；若账户已经关联另一个本局参与者，不自动合并两个座位、角色或推测，返回明确冲突提示并保留原状。说书人可以按现有管理流程处理多余游客，但系统不会因登录自动删除或腾空座位。

同一页面网络掉线后继续 WebSocket 重试，掉线不自动释放座位。刷新或重新打开时先用现有 Cookie 查询会话；网络超时、离线或服务端临时错误保留本地登录状态并显示重试，不跳回加入页。只有服务端明确返回会话无效或账户已撤销，才清理页面状态。同一设备、同一访问地址在 30 天有效期内自动登录；本地 IP、`localhost` 与公网隧道是不同浏览器来源，Cookie 不自动共享，换入口首次需再登录或续接。

游客丢失浏览器 Cookie 或换设备时，由说书人在本局玩家名单选择原参与者，生成一次性、10 分钟有效的续接码。玩家在“找回本局身份”输入房号和续接码，服务端核对局 ID、参与者、有效期、使用次数及频率限制，签发新设备会话并回到原座位；旧设备会话默认仍可用，说书人可以撤销遗失设备的本局会话。续接码只授权本局参与者，不等于账户登录，不能读取该账户的跨局历史。仅凭名字、房号、座位号或旧公开 ID 不能认领身份。

游客没有可跨局验证的账户，因此离开后若未绑定账户，不保证跨设备找回历史。结束或重置前界面提示游客：想保留个人历史，应先注册并绑定当前身份。

## API、实时投影和权限

所有玩家私有 HTTP 操作从服务端会话解析参与者身份；原有 URL 或查询参数中的 `player_id` 至多是目标标识，必须与会话匹配，否则拒绝。`/api/me/{player_id}`、所有 `/api/player/{player_id}/*`、私聊接口及 WebSocket 都纳入这一规则。说书人管理接口保留独立认证，但说书人凭证不进入玩家会话。公开座位名单、聊天和玩家投影不含任何人的会话秘密、密码哈希或恢复码；普通玩家之间看不到彼此私有信息。

WebSocket 以已验证的会话绑定实际参与者，断线重连取服务端最新状态；不能靠 `who=<公开 ID>` 加入别人的频道。玩家被说书人移除或本局重置后，旧参与者会话失效并关闭其连接。说书人读取本局推测走现有说书人授权；账户历史接口只认账户本人，不给说书人跨局读取权限。

## 存储、归档和恢复

`backend/data/game.json` 继续保存当前局的座位和规则状态，并新增不可复用的 `game_id` 以及参与者与账户的关联；会话秘密和密码不写进此 JSON。`backend/data/accounts.sqlite3` 保存账户、密码哈希、会话摘要、续接码摘要、账户关联和按 `game_id` 唯一的历史归档。数据库文件不提交到 Git，按数据库一致性方式备份；换电脑或丢盘需要连同当前局 JSON 一起迁移或恢复，账户不是云同步服务。

说书人宣布结算后，玩家当前局页面可读自己的角色、推测与结果。说书人重置已开始或已结算的本局，或在这类局上更换配置之前，后端先为已关联账户的参与者归档本局记录；未结算时标记“未完成”，不编造胜负。大厅内单纯调整人数或剧本不生成空白历史。归档按 `game_id + account_id` 幂等，失败则中止清空本局，避免历史丢失；重试不能生成重复记录。账户历史只含本人角色／有据可查的角色变化、本人推测事件和最终结算，不含私聊；若事件记录不足，不补造变化时间。新局生成新 `game_id`，账户会话保留，旧参与者会话失效。

旧版本存档可被读取，但公开过的旧玩家 ID 不能自动兑换为新会话；旧局已结束时从新局开始使用新身份。任何清除旧存档或旧账号的运维操作都必须单独确认，不能作为迁移的隐含步骤。

## 页面和验收

玩家页面可选择游客加入、注册、登录、找回本局身份；账户页可查看本人历史、退出、修改密码、使用恢复码重置密码。登录后若已有本局参与者，直接进入原座位；若尚未参与，仍显示房间加入流程。说书人页可为已存在参与者签发或撤销本局续接码，不显示账户密码或历史。

验收必须覆盖：

- 同名重复加入不会自动取得原座位；账户重新登录和有效续接码能回原座位，且不改变角色、生死、夜晚状态和推测。
- 网络中断或服务器短暂不可达不清理身份；同地址刷新自动恢复，跨来源需重新登录或续接，撤销会话后立刻失效。
- 公开 ID、房号、姓名和座位号都不能访问他人的私有 HTTP、WebSocket、私聊或历史；说书人只看本局推测，不读账户跨局档案。
- 注册／登录／游客绑定／冲突处理、密码恢复、速率限制、CSRF 与 WebSocket Origin 拒绝均有自动测试。
- 结算、未结算重置、配置切换、重复归档和进程重启后，账户历史一致且只含本人角色、推测和结果；私聊不进入历史。
- HTTP 测试警告明确可见；账号使用测试专用密码，公网不暴露明文 HTTP；切换 HTTPS 只调整部署和 Cookie 安全标志，不迁移账户数据。
