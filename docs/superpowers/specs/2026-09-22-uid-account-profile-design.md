# 四位 UID、账户资料与昵称规则设计（待执行）

本设计是现有[玩家账户、游客续接与历史记录设计](2026-09-22-player-accounts-reconnect-history-design.md)的增量。当前 8000 服务不因本设计变更；先备份账户数据库与本局存档，再实施迁移和验收。

## 身份与登录

- 注册成功时为账户分配永久、唯一、随机的四位十进制 UID，范围 `1000`–`9999`；碰撞时重新抽取，不复用已分配号码。9000 个号码用尽时明确拒绝新注册，不循环覆盖。现有账户迁移时逐一补发 UID，并保留现有内部账户 ID、用户名、密码、会话、关联玩家和历史记录；UID 只是公开登录别名，不替代内部主键。
- 登录界面明确切换「用户名」和「UID」两种方式，**均须输入密码**；不用同一输入框猜测四位数字是旧用户名还是 UID，以免撞名。仅知道 UID 不能登录或认领座位。UID 可以在账户管理页复制和分享。登录错误统一表述，按来源与账户标识限速，防止枚举四位号码。
- 现有 30 天服务端会话继续承担同一访问地址上的自动登录；退出或会话过期后重新用用户名／UID 加密码登录。局域网地址与公网域名的 Cookie 不互通，不承诺跨地址免登录。

## 密码与昵称

- 按用户选择，密码长度下限改为 **4 个 Unicode 字符**；设计暂定上限 **128 个 Unicode 字符**，注册、改密、恢复及前后端校验保持一致，继续只保存 Argon2id 哈希。该下限只适合小规模测试，页面继续警示不要复用重要密码；公网入口必须使用 HTTPS，且需要登录限速。正式对外运营前应提高下限并评估存量账户过渡。NIST [SP 800-63B](https://pages.nist.gov/800-63-4/sp800-63b/authenticators/) 对单因素密码推荐至少 15 字符，四字符密码明显低于该标准。
- 账户显示昵称与现有登录用户名分离。昵称为 **1–8 个用户可见字符**：数字、字母、汉字、标点、符号和 emoji 混用时合计计算，不限制字符类别；组合 emoji 等按 Unicode grapheme cluster 计一个，而不是按字节或 JavaScript `length`。前后空白可裁去，但裁去后为空的昵称不可保存。校验与计数规则由后端统一裁定，前端展示剩余字数。
- 账户昵称全局不可重名，游客昵称在当前对局不可重名。比较重名时对昵称做 Unicode NFKC 和不区分大小写的标准化；保留用户原始显示写法。如果同名冲突，明确提示重新选择，不能自动改名、占用别人账户或按姓名续接身份。
- 昵称变更后更新本局玩家展示及实时圆桌视图，但不重写既有聊天和审计事件中的历史姓名快照。旧存档中超过 8 字或重名的昵称先保留，不在迁移中静默截断、改名或踢出在线玩家；在其下次主动改名时执行新规则。若旧账户迁移后出现规范化冲突，标记待处理并允许原账户继续登录，不将冲突姓名授给新账户。

## 账户管理界面

- 增加独立「账户管理」入口，显示 UID、登录用户名、当前昵称、头像、自动登录状态、历史记录，以及改昵称、上传／更换头像、改密码、退出等操作；只有本人账户会话可编辑。游客不分配 UID，可继续按已有游客续接机制参与。
- 头像显示给同局玩家和说书人，但上传接口只能改本人头像。服务端校验大小（暂定最大 2 MiB）和真实图像类型，仅接受 PNG、JPEG、WebP，解码并重新编码后存储，拒绝 SVG/HTML 等主动内容；不返回服务器文件路径。无头像时使用默认图像；更换头像和刷新／重连后视图保持一致。
- 排查已有有效游客 Cookie 却缺少 CSRF 头时注册返回「安全令牌无效」的路径：注册／登录前先恢复或更新合法 CSRF 状态，不以禁用 CSRF 代替修复。账户页的「HTTP 测试」提示根据实际访问协议显示，不把 HTTPS 误写成 HTTP；本地 HTTP 测试提示与公网 HTTPS 配置分别验证。正式仅 HTTPS 时再启用对应 Secure Cookie 策略，避免破坏仍需使用的本地 HTTP 会话。

## 实施与验收顺序

1. 为 UID、昵称标准化与 8 个可见字符计数写边界测试；对账户 SQLite 做一致性备份和可回滚迁移。先补发旧账户 UID，再开放新注册；UID 碰撞、耗尽和进程重启均不能重复发号。
2. 实现 UID＋密码登录、4–128 字符密码校验、限速与账户资料接口；验证旧用户名登录、历史、续接、自动登录和账户恢复均不回退。账号枚举和 UID 单独登录必须失败。
3. 实现账户管理与头像上传，验证昵称重名／空白／中英文数字 emoji 混排的 8 字限制、游客局内重名、正在游戏的玩家改名同步和旧局名字不被静默改写。
4. 回归测试旧游客 Cookie 的 CSRF 场景、HTTP／HTTPS 提示及相应 Cookie 行为；完成前后端构建与本地手动验收后，备份并部署到 8000。不在现场进行中的局上做破坏性测试。

本条仅为计划和设计，尚未实施或测试。
