# 剧本、推理魔典、复盘与配乐整合计划

## 现状与回退点

- 当前工作分支：`codex/full-expansion`。`1e3ee65` 为扩展前工作区快照，`4464982` 合并了账户、自动登录、续接与历史记录。
- 用户允许直接操作现有工作区与端口；最终统一由 8000 提供服务。运行中的 `backend/data` 必须备份并保留。
- 旧局兼容；新功能不得泄漏真实角色或其他玩家推测，不得让推测改变游戏规则。

## 执行顺序

1. 剧本导入：获取六张板子的可核验 JSON/PDF 来源；构建数据驱动导入、校验、夜序和角色目录。对无法核验的角色规则明确标记人工说书人处理，不伪装为自动化。为 JSON 与既有板子写回归测试。
2. 玩家推理：按既有设计文档实现私有追加式笔记、鉴权、保存、实时推送、独立环形座位编辑，以及说书人只读查看。先写越权与重连失败测试，再实现。
3. 复盘：结算后对照本人推测与可靠的真实记录，旧局缺少证据时显示“无法核对”；账户历史可进入旧局只读复盘。
4. 说书人 BGM：获取可再分发的 CC0 音源、记录署名和许可证；阶段自动映射、手动切换、音量与静音，浏览器需首次点击激活。玩家端不播放。
5. HTTP/HTTPS：保留本地 HTTP，公网通过已有 HTTPS 隧道验证；记录正式 HTTPS 迁移所需的 Cookie、反向代理及域名条件。
6. 全量测试、前端构建、数据备份、部署重启到 8000，检查局域网与公网入口；按功能做小提交并记录未解决的问题与可选方案。

## 验收约束

- 任意玩家不能读取、改写其他玩家推测；说书人可实时只读查看。
- 角色候选与剧本目录一致，夜序不会因为未知角色执行错步骤；缺少可靠源时不编造。
- 推测持久化，掉线、重连、服务重启后仍存在；旧游戏状态不被测试污染。
- BGM 无版权不明素材；播放器不会影响玩家端。
- 最终服务和本地测试页面统一使用 8000，保留可回滚 Git 提交。

## 执行结果（2026-09-22）

- 五张有完整来源的板子已导入，脚本 JSON、夜序、角色图标与来源清单已提交。《罂粟花开》仍缺作者可核验的完整角色表，未伪造导入；取得 JSON 或双面 PDF 后继续。
- 玩家私有推测、实时说书人只读视图、账户归档与谨慎核对的复盘已完成；账户／游客续接与自动登录沿用本分支合并的实现。
- 八种场景 CC0 配乐只放在说书人端；本地 HTTP 与现有 HTTPS 隧道均已返回 200。正式全 HTTPS 化仍需要固定 HTTPS 域名／代理与 Cookie 策略，不能在保留本地 HTTP 登录的同时直接全局启用 Secure Cookie。
- 游戏与账户数据库已在 `backend/data/backup-20260922-TGEkQ2/` 备份。终版部署在 8000，自动测试与生产构建通过。图形浏览器验收因本机处于锁屏状态未执行，需解锁后由人手动确认布局和声音。

## 后续待执行：夜晚发信、玩家提交与寡妇魔典

设计与验收明细见 [夜晚交互与寡妇限时魔典](../specs/2026-09-22-night-interaction-refinements-design.md)。本项**仅列入计划，尚未实施**；当前 8000 服务与验收局不变。

- 厨师每次行动只向玩家发送**一条数字信息**。陌客／间谍登记或异常状态需要说书人裁定时，先完成裁定再发送；同一步重复点击或网络重试不得生成多份有效草稿或重复发信。
- 玩家夜晚选择经服务端确认后立即关闭该操作区，固定显示「说书人已收到」；刷新／重连保持收件状态。玩家不得修改、重交或撤销该次选择，说书人保留单独的纠错／撤销流程。
- 说书人右侧行动区实时显示行动座位的中毒／醉酒状态、来源及持续情况；发送信息前再次提示并记录发送当时的状态与真假标记，玩家端不泄漏这些异常状态。
- 寡妇在首夜轮到其步骤后，可在本人私密魔典直接看所有座位的真实角色与认知覆盖角色（如酒鬼自认身份）；提交选择后仍可查看，到天亮即回收。服务端鉴权，不因界面隐藏而继续暴露数据。
- 疯子有选刀步骤的夜晚先提交目标；真恶魔开始当夜选刀前，玩家端必须清楚显示疯子选了几号，并由说书人右栏同步显示以便线下传达。真恶魔仍独立选择自己的目标，不能自动沿用疯子的目标；刷新／重连仍能看到，其他玩家不可见。
- 先做重复提交、单条发信、刷新续接、异常提示与寡妇授权边界测试，再备份数据和部署。

## 后续待执行：四位 UID 与账户资料管理

设计与验收明细见 [四位 UID、账户资料与昵称规则设计](../specs/2026-09-22-uid-account-profile-design.md)。本项**仅列入计划，尚未实施**；当前 8000 服务与正在进行的局不变。

- 注册时分配唯一、永久的四位随机 UID，可用原用户名或 UID **加密码**登录；保留内部账户 ID、旧账户资料、30 天自动登录和历史记录。旧账户安全补发 UID，号码用尽明确报错。
- 密码按要求可从 4 个字符起，暂定最多 128 个字符；继续哈希存储、限速并警示测试密码风险。账户管理页展示 UID，支持修改昵称、密码、头像、查看历史与退出。
- 昵称不限制字符种类，但最多 **8 个用户可见字符**：数字、字母、汉字、符号、emoji 全部合计；账户昵称全局唯一，游客昵称本局唯一。旧昵称迁移不静默截断或改名。
- 修复旧游客会话导致注册 CSRF「安全令牌无效」的场景，以及 HTTPS 打开时仍显示「HTTP 测试」的提示；验证本地 HTTP 与公网 HTTPS 各自的会话和安全边界。先写回归测试、备份，再部署验收。
